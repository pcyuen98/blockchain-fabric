How to Start and Use the Minimal Fabric POC

This is a CLI-only Hyperledger Fabric network: one Org1 peer, one Raft orderer, and the Basic Go asset chaincode. Fabric CLI binaries run on the host. Docker Compose starts the Fabric services; no CA, CouchDB, Java, or client application is used.

Prerequisites

  • Linux or macOS with Bash, Docker Engine, and Docker Compose v2.
  • Fabric 2.5 CLI binaries (peer, configtxgen, cryptogen, and osnadmin) in the repository's bin/ directory, and Fabric configuration in config/.
  • The Basic Go chaincode source in ../asset-transfer-basic/chaincode-go.
  • jq and curl.

If the Fabric binaries, configuration, or images are not installed yet, run this once from the repository root:

./install-fabric.sh --fabric-version 2.5.16 binary docker

The network script uses pre-generated certificates when present; otherwise it creates the one-peer/one-orderer certificates with cryptogen.

Start the network

cd test-simple
./network.sh up

up starts the peer and orderer, creates the default mychannel channel, joins the peer, and installs/approves/commits the basic chaincode. It is safe to run again; an existing channel, chaincode definition, and ledger are preserved. The POC uses host ports 17050 (orderer), 17051 (peer), and 17053 (orderer admin) so it can run alongside an existing Fabric test network. Set a different channel with CHANNEL_NAME=mychannel2 ./network.sh up, or override a host port with PEER_PORT=27051 ./network.sh up.

Create, read, update, and delete an asset

Commands use the host Fabric CLI and submit transactions to the peer. Asset size and appraised value must be non-negative integers.

./network.sh create asset100 blue 10 Alice 500
./network.sh query asset100
./network.sh update asset100 green 12 Bob 750
./network.sh query asset100
./network.sh delete asset100
./network.sh query asset100

create and update take an ID, color, size, owner, and appraised value. delete and query take an asset ID. The final query should report that the deleted asset does not exist.

Restart and stop

./network.sh restart
./network.sh down

restart restarts the running services, then verifies the channel and chaincode without discarding ledger data. down stops the containers but retains named volumes; running ./network.sh up later resumes the same ledger.

Persistence: The peer's named Docker volume stores the ledger and world state. Do not remove Compose volumes if you need to keep assets. This single-organization setup is for local development and POC use, not production.
