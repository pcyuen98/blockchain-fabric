Local development walkthrough

Run the Fabric Gateway Spring Boot app

This sample connects a Java Spring Boot REST service to the local Fabric test network using the Fabric Gateway client. It demonstrates evaluating read-only transactions and submitting ledger writes against the Asset Transfer chaincode.

Commands assume the repository is at /path/to/fabric-samples. Replace that path as needed. The test network and its development identities are for local learning, not production.

1. Prerequisites

  • Docker Engine or Docker Desktop with Compose, or the Docker-compatible Podman setup shown in your terminal.
  • Fabric binaries, configuration, and container images installed for the repository's Fabric version.
  • Java 17 or newer and Maven 3.8 or newer.
  • Go and jq if you need to deploy the example chaincode.
docker --version
docker compose version
java -version
mvn -version

The Fabric Gateway client runs on the host and connects to Org1's published peer endpoint localhost:7051. It reads the Org1 development certificate and private key generated in test-network/organizations.

2. Start the Fabric network and deploy chaincode

In one terminal, start the network, create mychannel, and deploy the Go Asset Transfer contract:

cd /path/to/fabric-samples/test-network
./network.sh up
./network.sh createChannel -c mychannel
./network.sh deployCC \
  -c mychannel \
  -ccn basic \
  -ccp ../asset-transfer-basic/chaincode-go \
  -ccl go

Wait for chaincode deployment to finish successfully. If you already created the channel using ./network.sh createChannel -c mychannel, keep it and deploy the chaincode; do not recreate the channel. The app expects the channel name mychannel, chaincode name basic, and the Org1 peer at localhost:7051.

3. Build and start Spring Boot

In a second terminal, run the following from the application directory:

cd /path/to/fabric-samples/test-network/spring-boot-fabric-gateway
mvn clean package
mvn spring-boot:run

Maven downloads the application dependencies, compiles the service, and starts it on http://localhost:8080. Keep this terminal open while testing. The application uses the generated Org1 User1 identity and TLS certificate from the local test network.

Run from this directory. The default certificate path in src/main/resources/application.properties is relative to spring-boot-fabric-gateway. Starting Maven elsewhere may cause a missing certificate or key error.

4. Check the service

curl -i http://localhost:8080/api/health

A running service returns HTTP 200 and:

{"status":"UP"}

This endpoint checks that Spring Boot is responding; the transaction examples below additionally verify the Gateway connection, channel, and deployed chaincode.

5. Submit and evaluate ledger transactions

Initialize the sample ledger

curl -i -X POST http://localhost:8080/api/assets/init

The response confirms that InitLedger was submitted. The sample function creates its initial assets; call it once on a fresh ledger. Repeating it can fail because those asset IDs already exist.

Read all assets

curl -i http://localhost:8080/api/assets

Create an asset (write)

curl -i -X POST http://localhost:8080/api/assets \
  -H 'Content-Type: application/json' \
  -d '{
    "id": "spring-asset-001",
    "color": "green",
    "size": "5",
    "owner": "alice",
    "appraisedValue": "400"
  }'

Read the asset (evaluate)

curl -i http://localhost:8080/api/assets/spring-asset-001

Transfer the asset (write)

curl -i -X PUT http://localhost:8080/api/assets/spring-asset-001/transfer \
  -H 'Content-Type: application/json' \
  -d '{"newOwner":"bob"}'

Read the asset again to confirm that its owner is now bob.

6. API reference and troubleshooting

Method and pathGateway transactionPurpose
GET /api/healthNoneCheck Spring Boot is running
POST /api/assets/initInitLedgerSubmit initial sample assets
GET /api/assetsGetAllAssetsEvaluate and list assets
GET /api/assets/{id}ReadAssetEvaluate one asset
POST /api/assetsCreateAssetSubmit an asset creation
PUT /api/assets/{id}/transferTransferAssetSubmit an ownership transfer
  • Connection refused: confirm the test network is running and Org1 peer port 7051 is available.
  • Missing certificate or private key: start Maven from the application directory and confirm the network generated test-network/organizations/peerOrganizations/org1.example.com.
  • Channel or chaincode not found: check that mychannel exists and the basic contract deployment completed.
  • Duplicate asset: use a new asset ID or read the existing ledger state; do not submit InitLedger repeatedly.

7. Stop the services

Stop Spring Boot with Ctrl+C in its terminal. When finished with the network, stop and remove its containers and volumes from test-network:

cd /path/to/fabric-samples/test-network
./network.sh down
Data removal: network.sh down removes the local peer ledger data and generated network artifacts. Do not run it if you want to keep the current ledger.

See the application README for project details and the test-network tutorial for the broader Fabric network workflow.
