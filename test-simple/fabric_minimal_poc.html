Minimal Hyperledger Fabric POC — Store One Asset

Goal: Use the Fabric CLI to create and store one asset (asset100) on a single-organization Fabric network. No Java or Node.js client application is required.

Runtime: 3 Fabric containers (1 Peer, 1 Orderer, 1 Basic Chaincode runtime), with the peer CLI running on the host. LevelDB is embedded in the peer, not a separate container.

    CC-->>P: Read/write set
    P-->>CLI: Signed endorsement
    CLI->>O: Submit endorsed transaction
    O-->>P: Deliver ordered block
    P->>P: Validate endorsement and transaction
    P->>DB: Append block and update world state
    P-->>CLI: Commit event (with --waitForEvent)
    Note over DB: asset100 persisted in peer storage

The CLI invokes chaincode and submits the endorsed transaction. LevelDB stores current state; block files store the transaction history.

CLI Command — Store One Asset

After setting the Fabric CLI environment variables for your peer, orderer, TLS certificates and admin identity, run:

peer chaincode invoke \
  -o 127.0.0.1:7050 \
  --ordererTLSHostnameOverride orderer.example.com \
  --tls \
  --cafile "$ORDERER_CA" \
  -C mychannel \
  -n basic \
  --peerAddresses 127.0.0.1:7051 \
  --tlsRootCertFiles "$CORE_PEER_TLS_ROOTCERT_FILE" \
  -c '{"Args":["CreateAsset","asset100","blue","10","Alice","500"]}' \
  --waitForEvent

Assumes a channel named mychannel, deployed basic chaincode, valid CLI credentials, and an endorsement policy satisfiable by this one peer. The addresses and TLS files must match your actual setup. This command is for the proposed one-peer POC, not necessarily the existing two-organization test network.

Where the Asset Is Stored

DataTypical path inside peer container
Current asset state (LevelDB)/var/hyperledger/production/ledgersData/stateLeveldb/
Committed blockchain blocks/var/hyperledger/production/ledgersData/chains/chains/mychannel/

Persistence: Mount /var/hyperledger/production on a persistent volume or bind mount. The ledger is stored by the peer, not the orderer or chaincode container.

POC Prerequisites

A one-organization channel must exist, the basic chaincode must be deployed, the peer must be joined to the channel, and its endorsement policy must permit endorsement by the single peer. Pre-generated MSP/TLS certificates are sufficient; no running CA container is needed.
