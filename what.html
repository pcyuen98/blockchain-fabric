Best Fabric starting point with Docker Compose

Recommended network: test-network

For the easiest Docker Compose-based Fabric network in this repository, start with test-network. The root README identifies it as the local Compose network used by the other samples. It has one peer in each of two organizations and a single Raft ordering service. Its network.sh script generates identities and starts the Compose services in the right order.

The best first application to run on that network is asset-transfer-basic, which demonstrates creating, reading, updating, and transferring ledger assets. It is not a standalone Compose network: it depends on test-network. Start the network first, then deploy this sample's chaincode and run its client.

Why this is the easiest option

  • It is the repository's documented Docker Compose foundation for local Fabric development.
  • network.sh selects the Compose files, generates cryptographic identities, and starts the containers.
  • It separates starting nodes, creating a channel, and deploying chaincode, so each stage can be verified.
  • It avoids hand-writing Compose configuration or mounting certificates manually.

How to set it up with Docker

1. Install prerequisites

Install Docker Engine or Docker Desktop with Compose, and install the Fabric sample binaries, configuration, and matching container images using the official Fabric installation guide. The network checks that the local Fabric CLI and peer image versions match. The chaincode example below also needs Go installed. 

docker --version
docker compose version

See Install the Samples, Binaries, and Docker Images if peer, config, or the Fabric images are missing.

2. Open the test network directory

cd /path/to/fabric-samples/test-network

3. Start the network using the helper script

Run the helper rather than invoking a Compose file directly. It creates the organization certificates required by the peer and orderer mounts before starting the services. 

./network.sh up

The default uses Fabric cryptogen for local development identities and Compose files in test-network/compose. To use Fabric Certificate Authorities instead, add -ca to the network start command (the CA client binary and CA images must also be installed).

4. Create a channel

./network.sh createChannel -c mychannel

This creates the channel, joins both organization peers, and updates their anchor-peer configuration. If the network is stopped, createChannel can also start it automatically.

5. Deploy a smart contract

For example, to deploy the basic Go chaincode sample:

./network.sh deployCC -c mychannel -ccn basic -ccp ../asset-transfer-basic/chaincode-go -ccl go

This packages the Go chaincode, installs it on both peers, gets both organizations to approve its definition, and commits that definition to the channel. The sample client initializes the ledger when it runs.

6. Verify the containers are running

docker ps

You should see orderer.example.com, peer0.org1.example.com, and peer0.org2.example.com. A CA container appears only when the network was started with -ca.

7. Optional: interact with the network using peer CLI

Set the environment for Org1 or Org2 and run Fabric CLI commands:

export PATH="${PWD}/../bin:$PATH"
export FABRIC_CFG_PATH="${PWD}/../config"
export $(./setOrgEnv.sh Org1 | xargs)
peer channel list
peer chaincode list --installed

8. Stop and clean up

./network.sh down

This stops the network and removes its volumes, including ledger data. Run it only when you are ready to discard the local state.

What the Docker Compose setup looks like

The actual Docker Compose files used by the project live in the following location: 

test-network/compose/compose-test-net.yaml
test-network/compose/docker/docker-compose-test-net.yaml

The first file defines the shared peer and orderer services; the Docker-specific overlay supplies Docker settings. Optional Compose files add CouchDB or Certificate Authorities. network.sh chooses the appropriate files and handles prerequisites. Running these YAML files by hand skips identity and channel setup and is not the recommended first-time setup.

How the other Compose samples compare

The repository also contains Compose variants for the test network's BFT, CA, CouchDB, and Org3 configurations, plus add-ons for external chaincode and blockchain exploration. These extend a configured network or solve a narrower task rather than providing a simpler first Fabric setup.

SampleWhat Compose startsWhy it is not the easiest Fabric starting point
asset-transfer-basic Its REST API Compose file starts a Node application and Redis. It expects the fabric_test network and a deployed asset-transfer contract first.
token-sdk Multiple issuer, auditor, owner, and supporting services. It needs Fabric setup, token chaincode, generated keys, and additional Go dependencies.
token-sdk/explorer Explorer and database services. It expects the external fabric_test network and mounted connection-profile and crypto files.
asset-transfer-basic/chaincode-external External chaincode service containers. It requires an existing network and chaincode environment and is an advanced deployment pattern.
test-network/prometheus-grafana Prometheus and Grafana monitoring services. It monitors a test network that must already be running.
test-network-k8s Kubernetes resources rather than a Docker Compose setup. It adds Kubernetes and cluster configuration requirements.

Recommendation

For the simplest Compose-backed Fabric network, use test-network. For a beginner end-to-end example after that network is ready, use asset-transfer-basic.

A concise setup is cd test-network && ./network.sh up && ./network.sh createChannel -c mychannel.

Continue with the detailed test-network tutorial to deploy chaincode and exercise the sample application.
